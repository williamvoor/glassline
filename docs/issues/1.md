# 1. A reply that stops after the prose, with no UI, is shown as the answer

**Status:** open · **Opened:** 2026-11-03 · **Source:** the SPEC §17 A17-M2 scenario runs (`explorer/SPEC.md` §17, raw runs under `docs/scenarios/austender/`)

Repo rules apply (`CLAUDE.md`, `explorer/SPEC.md`). New behaviour starts as a dated amendment with an ADR. Before the fix, write a regression test that fails for the reason described. Tests must never call a real model. Paths are relative to `explorer/agent/`, and code is named by symbol, not line number.

**Problem.** When the model's reply has no `<a2ui>` block, `UiPipeline.build` (`ui.py`) treats
it as a valid prose-only reply. That is right for some answers: `no-such-agency` and
`write-request` are prose only by design. But it also lets through a reply that stopped early,
after the SQL had run and returned rows. The user sees a sentence ending in a colon and no
numbers.

**Evidence.** In `runs-20261103T052659Z.jsonl`, `cancelled-fy2425` run 2 has the prose
"In **financial year 2024-25**, by `publish_date`:" and nothing else. Its model call returned
87 completion tokens (`agent-20261103T052659Z.log`, 16:29:02). The `run_sql` before it had
returned one row. The scenario failed `no_visual` and `missing`. Seen in 1 of 30 runs on
2026-11-03, and the rerun (`runs-20261103T053148Z.jsonl`) passed 3 of 3.

**Options.**
- Ask for one Repair when the Turn's `run_sql` calls returned rows and the reply cites no
  Result, in neither the prose nor the UI. A Turn whose SQL returned no rows can still be
  answered in prose. The cost is one model call (about 2–4 s), only when the rule fires.
- Leave it. It is rare, and the Repair rule could fire on a good answer that rightly cites
  nothing.

**Unknown.** How often the rule would fire on good answers. Running all reviewed scenarios
with the rule only logging would show it.
