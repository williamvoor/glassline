# 11. Glimmer on the serverless training sampler takes 30–120 s to the first token

**Status:** closed: split stopped (user, 2026-11-05; ADR 0031 and 0042 deprecated) · **Opened:** 2026-11-05 · **Source:** Glimmer server smoke test (explorer SPEC §19, `specs/glimmer-server/SPEC.md`)

## Problem

The Glimmer server works end to end on s225: valid Express, `finish: stop`, usage reported. But each call took **36–121 s**, almost all of it waiting before the first token. §19's speed case assumes a Glimmer call costs 3–5 s. Spark's whole Turn is 6.3 s at p50. At today's latency the split can't pass the speed gate, however much of Spark's output it saves.

## Evidence

- **Checkpoint:** s225, from `glimmer-tune/runs/sft2/manifest.json`.
- **Prompt:** glimmer-tune's frozen system prompt (4,970 prompt tokens) and a one-line request. The reply was 84 tokens, sampled greedily.
- **Through the server** (`POST /surface`, 2026-11-05 08:50–08:53 local): 81.9 s and 85.7 s.
- **Direct probe** (the backend's sampler, `sample_with_prompt_tokens_result`, 2026-11-05 ~08:55):

| Call | Client s | `server_ttft` s | `server_processing_time` s | Attempts | Cached tokens |
|---|---|---|---|---|---|
| 0 | 121.2 | 117.2 | 120.4 | 1 | 0 |
| 1 | 35.8 | 31.3 | 34.5 | 1 | 0 |

- **No retries:** one attempt with HTTP 200 each time. The time is server side, before the first token. Generation itself took about 3 s.
- **No caching:** 0 cached tokens on all 4 calls, all with the same prompt and the same `prompt_cache_key`. In the latency run of 2026-11-03/04, s225 on the same pool was 3.1 s at p50 and 8.3 s at p95 (`glimmer-tune/SPEC.md`, run 2 latency; `docs/run2-decision-memo-20261104.md`).
- **Not measured:** the queue and prefill split (`prefill_queue_duration` is not reported on serverless).
- **Cost:** about $0.04 for the 4 calls.

## Options

1. **Re-measure at other times of day.** Small samples, about $0.01 per call. That shows whether this was a busy hour or the pool's normal state now.
2. **An on-demand Glimmer deployment.** ADR 0031 rejected it for cost: about $8/h for an H100, about $5,800 a month always on. It could be used only for the A2 measurement window.
3. **Stop the split.** Spark keeps writing the Surface. glimmer-tune stays an eval and research track.

## Unknown

- Whether Fireworks deprioritises sampling on the training pool, and whether that is temporary. This ties into the open question in §19 about Fireworks' terms for serving from the training sampler. Only the user can ask them.
- Why there is no prompt caching on this route.

## Decision needed

- Before Stage 0 and the agent-side build (§19 A1): pick an option above. Stage 0 measures Spark's share of the Turn, and it is no longer the binding constraint while Glimmer's first token takes 30 s or more.
