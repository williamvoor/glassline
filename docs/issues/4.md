# 4. `currency_compact` table columns show small values as `$0.0B`

**Status:** open · **Opened:** 2026-11-03 · **Source:** the SPEC §17 A17-M2 scenario runs (`explorer/SPEC.md` §17, raw runs under `docs/scenarios/austender/`)

Repo rules apply (`CLAUDE.md`, `explorer/SPEC.md`). New behaviour starts as a dated amendment with an ADR. Before the fix, write a regression test that fails for the reason described. Tests must never call a real model. Paths are relative to `explorer/agent/`, and code is named by symbol, not line number.

**Problem.** In `DataTable` (`macros.py`), a `currency_compact` column uses one unit, picked
from its largest value. One large row then makes every smaller row unreadable. The data is
right, but the screen hides it.

**Evidence.** In `runs-20261103T052659Z.jsonl`, `follow-up-first-supplier` run 3, the table
"Largest contracts for top supplier, 2024-25" shows `$3.4B` for CN4095604 and `$0.0B` for the
other 19 rows.

**Options.**
- Tables pick the unit per cell (`$3.4B`, `$45.2M`). Charts keep one unit, because their axis
  needs it.
- Keep one unit per column, which makes rows easy to compare, but fall back to per-cell units
  when the column's values span more than a set factor.
- Keep one unit, but show more decimals for small values.

**Decision needed.** The shared unit looks deliberate, so whether to change it is the
project owner's call.
