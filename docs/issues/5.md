# 5. Click metadata overwrites a plotted column named `_row`

**Status:** open · **Opened:** 2026-11-03 · **Source:** code review and re-review, reproduced with a stored fixture Result

**Priority:** P2

**Problem.** `_chart_values` in `explorer/agent/src/explorer_agent/macros.py` stores the
clickable row index in each chart datum under `ROW_FIELD` (`_row`). If the Result's `x`, `y`
or `color` column has that name, this overwrites the plotted value. Charts are clickable by
default, so an otherwise valid Result can silently show incorrect numbers or categories.
Both the uncoloured and colour-grouped branches write this field.

**Evidence.** A fixture Result with columns `name` and `_row`, rows
`{name: "A", _row: 100}` and `{name: "B", _row: 50}`, and a
`BarChart(result_id, "name", "_row", "T")` produces chart data containing
`{name: "B", _row: 1}` and `{name: "A", _row: 0}`. The measures have become row indices.
This needs neither a database nor a model call to reproduce.

**Options.**

- Give chart data internal field names that cannot collide with Result column names, and
  update the Vega encoding and client click handler together.
- Allocate an unused metadata field per chart and carry its name to the client.

**Acceptance criteria.**

- Add a failing regression test for `_row` used as each of `x`, `y` and `color`.
- Plotted values and labels remain faithful to the Result, with clicks still identifying
  the original row correctly.
- Cover both colour-grouped and uncoloured charts, and preserve existing folding and row-cap
  behaviour.
